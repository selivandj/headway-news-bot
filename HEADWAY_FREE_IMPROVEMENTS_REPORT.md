# Отчет по бесплатным улучшениям Headway Telegram Bot

Дата отчета: 2026-06-10  
Проект: Telegram-бот для канала Headway / новости про ЭЗС, электромобили и зарядную инфраструктуру  
Цель: выбрать из предложенных бесплатных доработок только полезные и безопасные, внедрить их без ухудшения качества постов и зафиксировать результаты.

## 1. Главный вывод

Из предложенного списка внедрены не все пункты, а только те, которые реально улучшают бота и не ломают редакционные правила канала.

Главное решение: не включать широкий автоматический поиск картинок через случайную выдачу DuckDuckGo/Wikipedia. После прошлых ошибок с неподходящими изображениями это слишком рискованно. Для канала безопаснее такая логика:

1. Сначала брать оригинальные изображения из статьи.
2. Если их нет, искать точное изображение по сущностям новости: модель станции, компания, город, событие.
3. Если точного изображения нет, честно сообщать владельцу: "у новости нет найденного медиа".
4. Генерировать изображение только после явной команды владельца.

То есть бесплатные инструменты можно использовать, но только как вспомогательные, а не как автоматический источник любых картинок из интернета.

## 2. Что было сделано

### 2.1. Добавлен отдельный парсер китайских источников

Создан файл:

```text
vps/parsers/china_sources.py
```

В нем реализован RSS-парсер китайского EV-направления без платных API. Сейчас он поддерживает:

- CnEVPost;
- CarNewsChina;
- ChinaDaily Auto;
- Google News China EV RSS.

Парсер делает:

- сбор статей из RSS;
- фильтр по EV/charging/battery-swap ключам;
- присвоение региона `China`;
- отметку языка источника;
- удаление дублей по ссылкам;
- короткий стабильный `id` статьи.

Результат: китайское направление можно расширять без Kimi/OpenAI и без прямого парсинга WeChat.

### 2.2. CarNewsChina добавлен в основной мониторинг

В основной список источников `vps/monitor.py` добавлен:

```text
CarNewsChina: https://carnewschina.com/feed/
```

Это хороший источник для китайских новостей, потому что он часто пишет о BYD, NIO, XPeng, Li Auto, батареях, зарядке и инфраструктуре в понятном английском формате.

Результат: бот получил еще один нормальный китайский источник без платной обработки и без сложного антибот-парсинга.

### 2.3. Добавлен бесплатный кэш поиска

Создан файл:

```text
vps/search/cache.py
```

Кэш хранит результаты во временных JSON-файлах и умеет:

- сохранять ответ по ключу запроса;
- возвращать результат, если срок жизни еще не истек;
- автоматически игнорировать устаревшие записи;
- не падать, если кэш-файл поврежден.

Результат: будущие бесплатные поисковые функции можно будет подключать аккуратнее, без лишних повторных запросов.

### 2.4. Обновлен пример настроек

Обновлен файл:

```text
.env.example
```

Добавлены и уточнены настройки:

```env
LLM_PROVIDER_CHAIN=gemini,groq,openrouter
TRANSLATION_QA_PROVIDER_CHAIN=gemini,groq,openrouter
CHINA_SOURCES_ENABLED=1
GOOGLE_NEWS_RSS=1
NEWS_SEARCH_ENABLED=1
SEARCH_CACHE_TTL_HOURS=24
IMAGE_SEARCH_ENABLED=1
ALLOW_WEB_IMAGE_SEARCH=0
```

Ключевое правило:

```env
ALLOW_WEB_IMAGE_SEARCH=0
```

Это защита от случайных изображений из интернета. Ее нельзя включать в автомате, пока нет надежной проверки, что картинка действительно относится к новости.

### 2.5. Проверены существующие команды для медиа

В `vps/bot.py` уже есть обработка ответов владельца на конкретный черновик:

- `ищи`;
- `поищи`;
- `найди картинку`;
- `найди фото`;
- `ищи картинку`;
- `ищи фото`;
- `сгенерируй`;
- `генерируй`;
- `сделай картинку`;
- `сделай изображение`.

Это значит, что отдельные slash-команды вида `/findimage` и `/generateimage` пока не обязательны. Текущая логика правильнее для Telegram: владелец отвечает прямо на нужный черновик, и бот понимает, к какому посту относится команда.

## 3. Что сознательно не внедрено

### 3.1. Автоматический DuckDuckGo Images как источник картинок

Не внедрено в автоматическом режиме.

Причина: широкий поиск картинок уже показал риск мусорных и неподходящих изображений. Для канала про ЭЗС это особенно опасно: картинка должна быть либо из оригинала, либо точно соответствовать станции/модели/компании из новости.

Статус: можно использовать позже только как ручной инструмент после дополнительной фильтрации.

### 3.2. Wikipedia Images

Не внедрено.

Причина: Wikipedia плохо подходит для новостей про конкретные зарядные станции, модели ЭЗС, локальные события и свежие релизы компаний. Она чаще даст общую или нерелевантную картинку.

### 3.3. Прямой парсинг WeChat

Не внедрено.

Причина: прямой WeChat scraping нестабилен, часто ломается, может требовать прокси, аккаунты, обход антибота и отдельную поддержку. Для текущей задачи лучше использовать CnEVPost, CarNewsChina и RSS/агрегаторы, которые уже выносят китайские новости наружу.

### 3.4. Генерация изображений через Replicate/Stable Diffusion

Не внедрено в этом шаге.

Причина: владелец уже зафиксировал правило: генерировать только после явной команды. Пока важнее надежно искать реальные изображения к новости.

### 3.5. Google Translate / googletrans

Не внедрено.

Причина: бесплатный перевод через неофициальные библиотеки часто нестабилен. Для черновиков канала лучше использовать текущую LLM-цепочку или писать простой краткий пересказ только при наличии понятного источника.

## 5. Успехи

1. Бот получил дополнительный китайский источник без платных API.
2. Появился отдельный модуль для китайских RSS, который можно развивать независимо от основного монитора.
3. Добавлен кэш, чтобы будущий бесплатный поиск не дергал источники без необходимости.
4. В настройках явно закреплено, что широкий web image search выключен.
5. Сохранена главная редакционная безопасность: бот не должен автоматически публиковать и не должен автоматически подставлять случайные картинки.

## 6. Ошибки и ограничения

1. Бесплатные источники не гарантируют стабильность. RSS может временно отдавать мало статей или быть недоступен.
2. Google News RSS может возвращать ссылки-обертки, а не прямые ссылки на оригинал. Для публикации желательно разворачивать их в оригинальный источник.
3. Без платного или надежного поискового API поиск точных изображений остается сложной задачей.
4. WeChat пока не подключен напрямую, потому что это отдельная сложная история с высоким риском поломок.
5. Полностью бесплатная LLM-цепочка может давать скачки качества, поэтому правила канала и валидаторы важнее конкретной модели.

## 7. Что улучшать дальше

### Приоритет 1. Точный поиск изображений

Нужно развивать не общий поиск картинок, а точный поиск по сущностям:

- название станции;
- модель станции;
- производитель;
- город/выставка/мероприятие;
- название продукта;
- источник новости.

Хорошая команда владельца:

```text
найди фото станции ФОРА
```

или:

```text
найди фото НАРТИС S90
```

Бот должен искать именно это, а не просто "charging station".

### Приоритет 2. Ручной режим для сложных медиа

Если бот не нашел медиа, он должен писать владельцу:

```text
Точного изображения не нашел. Могу поискать глубже по модели/компании или сгенерировать нейтральную иллюстрацию по команде.
```

Это лучше, чем подставлять случайную картинку.

### Приоритет 3. Статистика качества

Нужно сохранять в SQLite:

- какие черновики одобрены;
- какие отклонены;
- какие просили переделать;
- какие темы чаще доходят до публикации;
- какие источники дают хорошие новости;
- какие источники дают мусор.

Так бот будет учиться не только на тексте правил, но и на истории решений владельца.

### Приоритет 4. Разделить роли ИИ

Правильная архитектура:

- поиск новостей делает бот;
- китайский смысл может помогать разбирать отдельная модель;
- финальный текст всегда собирается по правилам канала;
- публикация только после подтверждения владельца.

Модель можно менять, но правила канала должны оставаться главными.

## 8. Итог

Бесплатные улучшения внедрены аккуратно: добавлены китайские RSS-источники, кэш и безопасные настройки. Опасные части из предложенного списка не включены в автоматический режим, потому что они могут ухудшить канал: особенно широкий поиск картинок и прямой WeChat scraping.

Текущая стратегия правильная: бот должен искать больше хороших новостей, но публиковать и подбирать медиа только под жестким контролем качества.
